Wide-layout & coach-panel parity

Bring the desktop surface to parity with the iPad-landscape quiz+coach split: a collapsible left nav and a coach column that stays usable as the conversation grows. Everything below is decided so engineering can lift it straight into an EARS spec — no further design clarification on A–F.

01

Decision log

Every question A1–F3 with a single clear choice and one line of rationale. Status tags mark alignment with the proposed engineering defaults. Two hard Reject calls: B1 (scope auto-collapse) and E1 (keep an in-place ask bridge).

A Information architecture / surfaces
A1 Accept
Share one "wide" layout system across desktop & iPad, or keep distinct surface labels?
Keep the three surface labels (iphone/ipad/desktop), but drive the split off a derived predicate isWide = surface !== "iphone". One layout system, one code path; labels still feed nav membership.
Why: the labels already carry semantics (Skill in nav, focus screens) — collapsing them risks those; a boolean seam is the minimal change. FR-J1/J2/J3
A2 Refine
Minimum width for the split? What happens at ~481–900px?
Split requires ≥ 900px of content width (viewport minus any open sidebar). Below that, degrade in a fixed order: (1) collapse sidebar to icon rail → (2) if still < 900, hide the inline panel and offer a "Coach" control that opens it as an overlay drawer. Never stack coach below the item.
Why: a content-width trigger composes with sidebar state, so collapsing the nav can rescue the split before anything is hidden; stacking would break the height chain and shove the item off-screen.
A3 Refine
Is the right panel always visible, or dismissible / re-expandable?
Visible by default; the learner can dismiss it to a thin labeled edge tab and re-expand. Dismissal persists per session. Dismissed ≠ gone — the thread survives and stays reachable from the Coach nav item.
Why: desktop is new here and desktop users expect to reclaim width for a long stem; a reversible dismiss beats an all-or-nothing rule.
B Sidebar collapse
B1 Reject
Auto-hide after any nav selection, or only content-heavy screens?
Auto-collapse only when entering a content-heavy focus screen — Quiz, Coach, Skill, Test. Home and Progress keep the sidebar expanded. Rejects the blunt "auto-collapse after any nav" default.
Why: dashboards are navigation hubs — collapsing on arrival fights the user; the width win only matters where content is dense. FR-B1
B2 Accept
Does Dashboard/Home keep the sidebar expanded by default?
Yes. Home and Progress default to expanded; they are wayfinding surfaces, not focus surfaces.
Why: consistent with B1 — the collapse rule is keyed to the destination class, not the act of navigating.
B3 Refine
Reopen control: placement, label, keyboard, does a thin rail remain?
"Collapsed" = a persistent 56px icon rail, never a full hide. A chevron toggle (⟨ / ☰) at the rail top expands/collapses; aria-label "Expand / Collapse sidebar", real <button> (Tab + Enter/Space) plus a global [ shortcut. Icons keep hover tooltips + active state.
Why: a thin rail keeps every destination one click away — no trapped nav, meets ≥44px targets, avoids a disorienting blank gutter.
B4 Refine
Where does ThemeToggle live when the sidebar is hidden?
It never disappears. In the icon rail it becomes an icon-only toggle pinned at the rail bottom. Because we use a rail (not a full hide), theme is reachable on every screen.
Why: structurally forecloses the "sidebar-trapped theme" failure path called out in the brief. FR-K1
B5 Accept
Persist collapsed/expanded across routes and reloads? Session vs local?
Base preference persists in localStorage (preact.shell.sidebar), default expanded. The B1 auto-collapse fires on entering a content screen unless the learner explicitly expanded this session (a sessionStorage "user-pinned" flag wins).
Why: reload stability (local) without the auto rule fighting an explicit choice (session precedence).
C Coach column structure
C1 Refine
Quiz CoachPanel stacking order, zones labeled fixed / sticky / scroll.
Three zones, top→bottom: A · FIXED chrome (title, status, current-item line, mode pills) → B · SCROLL the log (role="log": opener → revealed nudge bodies → coach turns) → C · PINNED action cluster (One-more-nudge button, chip row, composer).
Why: moving nudge bodies into the scroll zone is what resolves the brief's height-physics problem — revealed text no longer competes with pinned chrome for vertical space. See wireframe W3. FR-J3a
C2 Refine
Same zone model for standalone /learn/coach (rail + strip). Differences?
Same zone model. Desktop rail: Back/Wrap-up header (fixed) + left context rail (fixed) + right column = scroll log over pinned chips+composer. iPad strip: identical, chrome is a top strip instead of a left rail. Differences vs panel: adds Back/Wrap-up + history line; no "One more nudge" (no per-item ladder off-quiz).
Why: one height-chain implementation, surface-specific chrome placement only. See wireframe W4. BP-1.5
C3 Accept
Revealed nudge texts: scroll, stay pinned under the button, or collapse?
They scroll with the transcript — rendered as coach-authored bubbles inside the log (tagged "Nudge 2 / 3"). Only the "One more nudge" button is pinned. Nudges do not collapse per-rung (they're one line each and form the ladder record).
Why: a single scrollable reading surface; nudges become part of the thread narrative rather than a growing pinned block.
C4 Accept
Chip row: pinned above composer, pinned under chrome, or scroll?
Pinned directly above the composer, inside the bottom cluster (Zone C).
Why: chips seed the composer ("Explain the rule simply" → input), so they're compose-adjacent actions and must never scroll away.
C5 Refine
Identical pin/scroll/collapse in panel vs standalone?
The zone model and collapsible-answer behavior are identical. Only chrome placement differs (stacked-top panel / left-rail desktop / top-strip iPad), and standalone drops "One more nudge" and adds Back/Wrap-up.
Why: one mental model + one implementation of the physics; surface chrome is the only variable.
D Collapsible answers
D1 Refine
What is visible in the collapsed state?
One summary row: a "Coach" label + the first sentence (truncated, ellipsis) + a relative timestamp + an expand chevron (▸). The paired user question stays visible above it (D3). The whole row is the click target.
Why: enough to recognise a turn while scanning; the question above supplies context so the first line need not repeat it.
D2 Accept
Auto-collapse rules?
When a new reply completes, auto-collapse all prior (non-error) coach answers; newest stays expanded; streaming stays expanded. A manual expand/collapse is remembered per-turn and always overrides the auto rule.
Why: keeps long threads scannable by default while honoring explicit intent — no fighting the user.
D3 Refine
User message bubbles: always expanded, or collapse with the pair?
User questions always stay visible. Collapse hides only the coach answer body; the user prompt remains as the label for the collapsed answer.
Why: the question is the anchor; hiding it would make collapsed answers unidentifiable and defeat scanning.
D4 Accept
Streaming stays expanded (confirm); Error+Retry when collapsed?
Confirmed: a streaming turn is force-expanded and cannot be collapsed until it completes. An errored turn is force-expanded and excluded from auto-collapse so its Retry stays visible.
Why: never bury a live spinner or a recovery action behind a chevron. FR-F3/F4
D5 Refine
a11y: how should aria-live / focus behave when collapsing mid-thread?
The log stays role="log" aria-live="polite". Collapse is a <button aria-expanded aria-controls> — it does not announce via the live region and does not move focus. Collapsed bodies use hidden (removed from the a11y tree). Auto-collapse of prior turns is silent; new streamed tokens still announce because the newest turn is expanded and live.
Why: no focus theft, no re-announcement of old content, new replies still reach screen readers. U4
E Feedback bridge & empty states
E1 Reject
Remove "Ask the coach" on wide Feedback, or keep as secondary?
Remove the navigate, but keep an in-place bridge: "Ask the coach about this" pins the item context and moves focus to the panel composer — no route change. At the narrow drawer width it opens the drawer. Rejects a clean "drop Feedback→Coach" reading of the default.
Why: the panel is already present so navigating is wrong, but the "take this to the coach" intent is valuable — preserve it as a focus bridge. iPhone keeps the navigate (no panel). FR-5
E2 Accept
Cold coach (no pin): layout change or only chrome copy?
Copy only, no layout change. Status reads "Ready when you are", the current-item line is omitted, and the empty log shows just the opener bubble.
Why: layout stability across warm/cold states; honesty is expressed in copy, not structure.
E3 Refine
Long stem left vs tall coach right: independent columns? linked height? who owns page scroll?
Two independent scroll columns; the window does not scroll on wide Quiz. The split row is height-locked to the viewport; the left (item) column scrolls internally if the stem+feedback overflow, the right (coach) column scrolls its log. Neither owns window scroll.
Why: generalises "scroll only the coach" to both columns; keeps composer, nudge, and both columns' chrome stable regardless of the other side's length.
F Visual / motion
F1 Accept
Sidebar collapse motion; reduced-motion rule.
A short 160–200ms ease-out on rail width + content reflow. Under prefers-reduced-motion: reduce → instant, no transition.
Why: a brief transition reads as "the same rail narrowing", not a jump; reduced-motion is honored.
F2 Accept
Answer collapse motion.
~150ms height + opacity on a single turn. When a new reply auto-collapses several prior turns, they change in one frame (no staggered cascade). Reduced-motion → instant.
Why: gentle and non-distracting; a cascade of animating rows on every reply would churn.
F3 Refine
Density change for the w-80 panel on desktop?
On desktop the panel grows from a fixed w-80 (320px) to a fluid clamp(340px, 32%, 460px); iPad keeps ≈320–360px. The item column takes the rest, capped at a ~680–720px reading measure.
Why: desktop has spare width — a slightly wider coach column improves chat readability; the clamp stops it dominating or starving the item.

05

Acceptance criteria draft

EARS-style, liftable into the SDD spec. Failure paths first.

Failure & edge paths
AC-1
IF content width is below 900px, THEN THE SYSTEM SHALL collapse the sidebar to the icon rail before hiding the coach panel, and shall never stack the coach below the quiz item.
AC-2
IF content width stays below 900px with the sidebar already collapsed, THEN THE SYSTEM SHALL hide the inline panel and present a "Coach" control that opens it as an overlay drawer without navigating away.
AC-3
WHILE a coach reply is streaming, THE SYSTEM SHALL keep that turn expanded and prevent it from being collapsed, manually or automatically.
AC-4
IF a coach turn is in an error state, THEN THE SYSTEM SHALL keep it expanded and its Retry control reachable, excluding it from auto-collapse.
AC-5
WHEN the last available ladder rung has been revealed, THE SYSTEM SHALL disable "One more nudge" with an explanation and shall not hide or displace the composer.
AC-6
WHILE the sidebar is collapsed, THE SYSTEM SHALL keep the theme toggle reachable within the icon rail.
AC-7
WHEN the learner collapses or expands a coach answer, THE SYSTEM SHALL not move keyboard focus and shall not re-announce prior content through the live region.
Nominal behavior
AC-8
WHERE the surface is wide (desktop or iPad), THE SYSTEM SHALL render the quiz item and the live coach panel side-by-side sharing one coach thread.
AC-9
WHILE on a wide Quiz surface, THE SYSTEM SHALL scroll the item column and the coach log independently and shall not scroll the browser window.
AC-10
THE SYSTEM SHALL keep the composer, chip row, and "One more nudge" control pinned and visible regardless of coach-log scroll position.
AC-11
WHEN a new coach reply completes, THE SYSTEM SHALL collapse all prior non-error coach answers and keep the newest expanded.
AC-12
WHEN the learner enters a content screen (Quiz / Coach / Skill / Test), THE SYSTEM SHALL auto-collapse the sidebar unless the learner explicitly expanded it this session; Home and Progress shall stay expanded.
AC-13
WHEN the learner dismisses the coach panel on wide Quiz, THE SYSTEM SHALL preserve the coach thread and keep it reachable from the Coach nav item.
AC-14
WHEN the learner activates "Ask the coach about this" on wide Feedback, THE SYSTEM SHALL pin the item context and move focus to the coach composer without navigating.
AC-15
WHERE prefers-reduced-motion is set, THE SYSTEM SHALL apply sidebar and answer collapse changes instantly, with no transition; otherwise the sidebar preference persists across reloads via localStorage.
06

Open risks

Needs an eng spike before the spec locks.

SpikeHeight chain on mobile Safari / iPad Safari
100dvh toolbar behavior + nested min-h-0 flex + overflow-y-auto can collapse on iOS. Device-test before committing the chain.
SpikePinned composer inside overflow ancestor
position:sticky can fail under a transformed/overflow parent — prefer a flex bottom cluster; verify with real content.
WatchNested / dual-column scroll chaining
Two independent scroll columns + a drawer → overscroll chaining on trackpad/touch. Apply overscroll-behavior:contain.
WatchAuto-collapse × aria-live
Confirm no double-announcement across browsers/SRs; confirm hidden removes bodies from the AX tree without breaking log semantics.
WatchDrawer focus trap + return focus
At the narrow width, the overlay drawer needs a focus trap and return-focus to the trigger (a11y).
WatchPanel width vs long tokens
Long code/URL tokens in coach markdown can overflow the clamped panel — need min-w-0 + wrap/break.
07

Explicit non-goals

Not redesigned in this pass.

✕iPhone tab bar & focus-mode chrome — untouched.
✕Question / hint bank content; hint-rung pedagogy (probe / conceptual / narrowing); the non-reveal guarantee.
✕Coach LLM behavior, prompts, or mode semantics.
✕Auth / WorkOS.
✕Backend / engine changes; any new npm dependency.
✕Dashboard / Summary / Skill / Progress / Test screen internals — only their shell chrome + sidebar behavior change.
✕Theme tokens / color palette.
Preserved invariants: one shared coach thread (panel ↔ /learn/coach), the reviewed hint ladder, and non-reveal nudges that never name the answer letter.
