- [ADR-0005: Subject-Coach engine home (Frontend-Ring local-first) + persistence substrate](0005-subject-coach-engine-home-and-substrate.md) — Splits the engine: learner-facing schema + FSRS + adaptivity + grading run on-device in the Frontend-Ring (honoring the UI spec's local-first §7 and ADR-0001 shells; FSRS is purpose-built for offline client use), while LLM generation + the coach run backend. Substrate = one Drizzle schema, Postgres-first but SQLite-compatible, **no sync engine yet** (the mature 2026 Postgres↔SQLite sync ecosystem makes deferral low-regret). Pairs with the data/protocols design doc.
- [ADR-0006: Subject-Coach component protocols (seven Frontend-Ring ports)](0006-subject-coach-component-protocols.md) — Defines the engine's contract surface as seven one-interface-per-module ports (`SkillTaxonomy`, `QuestionRepo`, `AttemptRepo`, `SessionRepo`, `Scheduler`/FSRS, `Grader`, `ContentRepo`) + a `CoachAgentClient` over the existing AG-UI SSE transport, plus a client-side renderer registry. The `Grader`/registry pair is the OCP seam that makes Math an extension (new adapter + registry entry + rows, zero engine edits); grading is pure + verifier-first (reuses the GoalJudge cascade discipline). Conforms to F-R3 + SDK-confinement from the frontend ports deep-dive.
- [ADR-0007: Subject-Coach agent — capability-gated tools + English-only input guardrail](0007-subject-coach-agent-tool-capability-gating.md) — Spins the coach from the existing `build_graph` pipeline and makes its AgentFacts contract **load-bearing**: `AgentFacts.capabilities` *filter the `ToolRegistry`* so the coach is bound only `think`+`file_io` (no `web_search`/`shell`/`python`), with an architecture test asserting *declared = bound* and a fail-fast on a capability naming a missing tool. Closes the real gap that no per-agent tool allow-list exists today (capabilities only gated sub-agent delegation). Also makes the `InputGuardrail.accept_condition` injectable → English-learning-only (broad: grammar/usage/rhetoric/reading/vocab/strategy), refusing off-topic at `guard_input`. Coach forks by prompt-param (no new graph node). All flag-gated, shadow-first.
- [ADR-0008: Subject-Coach judges — Grader, Grader Judge, and Pedagogy GoalJudge](0008-subject-coach-judges-grader-and-pedagogy.md) — **Accepted 2026-07-01, with conditions** (κ TPR/TNR floor for the answer-leakage detector before its flag is trusted in a gate; the `GoalJudge` `build_graph`-injection lands paired with the judges). Evaluates the general `GoalJudge` from the English-coach angle and finds it **cannot** be retargeted (its verdict schema has no correctness/answer-leakage/per-criterion axis; `verify_answer` is bound to generic constraints). Ships **three judges, maximal reuse**: a deterministic **MC Grader** (letter exact-match, frontend, offline), an LLM **Grader Judge** grading the coach's *dynamically generated content* (faithfulness/correctness/justification/actionability), and a **Pedagogy GoalJudge** with a first-class, never-averaged **answer-leakage** flag (+ mistake-id/location/actionability/coherence from the AI-tutor taxonomy, plus productive-struggle (Holt) + illusion-of-competence (Oakley) axes) — the general GoalJudge kept as-is for session-goal completion. Homes split per ADR-0005 local-first; the frontend MC Grader + backend judges compose ADR-0006's `Grader` port `Verdict`. Calibrated with κ reusing the ADR-0003 cascade + cert discipline; no live LLM in CI.
- [ADR-0009: Reflexion loop is offline-only for the Subject-Coach (not on the live conversational path)](0009-subject-coach-reflexion-not-on-live-path.md) — **Accepted 2026-07-01.** Evaluates whether to enable the pipeline's **T2 Reflexion** loop for the multi-turn coach and rules **no**: T2 is a *per-task retry* keyed on a GoalJudge task-failure verdict (a coaching turn has no such verdict — the student's reply *is* the loop); it converges toward *the correct answer*, the exact **answer-leakage** behavior the design forbids; it adds 2–3 LLM calls/turn on a latency-sensitive UX with no measured gain; and `reflections` has **no `task_id` guard**, so a prior turn's critique leaks into the next (a latent chat-wide bug, flagged as a separate fix + a hard prerequisite for ever enabling T2 in chat). General principle: inline Reflexion is for checkable single-task runs, not conversational turns. Reflection for the coach lives in the **offline judge layer** (the Pedagogy judge *is* turn-reflection). Grounded in 2026 reflection trade-off research + the Feynman/Oakley/Holt pedagogy (Reflexion rescues the answer; the coach must not). Its one hard prerequisite — the `reflections` cross-turn leak — was satisfied ahead of ratification by ADR-0005-reflections (`efc1715`/`27f1490`), so the ADR ratified clean (no conditions).
- [ADR-0011: Subject-Coach engine learner read port (Phase-1 skill_state reads only)](0011-subject-coach-engine-learner-read-port.md) — **Accepted 2026-07-01 (amended 2026-07-01 before ratification).** Amends ADR-0006 with one new read-only `LearnerReadRepo` port surfacing the Phase-1 learner reads the UI needs but no existing port exposes: `listSkillState`/`getSkillState` (Dashboard mastery grid FR-C3, Summary mastery-delta FR-G1). The FR-G1 before/after delta is specified: a UI-captured session-start snapshot in `use_quiz`/`use_session`, with session-resume as a documented decision trigger. The deferred `getTutorial`/`listProgressPoints` (D1, Screens 6/7) are **NOT** on this port — they wait for a second amendment gated on Screens 6/7 resuming, honoring the four-layer "build on the second consumer" rule + ADR-0010's on-device-SQLite deferral precedent (the original draft bundled them; the amendment split them out to avoid freezing port shape for the still-Proposed subjective plane ADR-0007/0008/0009). - [ADR-0012: Coach context contract — mode-dependent injection + offline leak-checked hint ladder](0012-subject-coach-context-contract-hint-ladder.md) — **Accepted 2026-07-02** (was Proposed 2026-07-01 by the agent detailed design's §10 adjudication; tightened 2026-07-02 with the residual-risk window, mechanical mode-spoofing enforcement, the no-assertion-rung decision trigger, and the Decision §3 advisory-mode clarifier; ratified at the build-sequencing step-1 human gate). Settles whether the live coach *sees the correct answer* with a **mode-dependent context contract**: **pre-submit** (quiz hint FR-D5, split-panel nudges FR-J3a) the context **excludes the four answer-bearing `Question` fields** (`answer_letter`, `per_choice_rationale`, `why_correct_md`, `why_tempted_md`) and hints come from an **offline leak-checked hint ladder** (probe → conceptual → directive; deliberately **no assertion rung**; per-rung leakage check in the generator's verifier cascade; `reviewed`-gated rows) that the coach *selects and paraphrases*; **post-feedback** ("Ask the coach" FR-E5, entered after the answer is on-screen) gets full context — leakage is moot by construction. The client-sent `mode` is advisory-only; the backend derives the authoritative `mode` from session state (mechanically enforced, not a prose check — the ADR-0011 lesson) — **amended 2026-07-02 with the session-state home**: a minimal **BFF coach-session marker store** (`{user_id, question_id, submitted_at}`, monotonic, written from the quiz submit path), because the engine DB is Frontend-Ring-local (verified: no server API touches attempts); the BFF derives mode from the marker and **strips the four answer-bearing fields from client-supplied context when derived mode = pre-submit** (two-layer assembly); interim authored rungs live in a backend-readable data asset beside `prompts/`; marker spoofing ≈ just submitting (stated honestly — the store buys authority, monotonicity, the audit carrier, one arch-testable seam). Grounded in the 66%-leak free-generation finding + MWPTutor finite-state slots; rejected always-full (prompt discipline fails), always-withheld (cripples post-feedback + faithfulness risk), and mode-dependent-without-ladder (free generation returns in the critical mode). **Residual-risk window stated:** until ADR-0008 cond#1 (the κ floor) is certified, the per-rung leak check is deterministic-only and the `answer_leakage` flag stays telemetry-only — context-leakage is solved on day 1; paraphrase-drift is bounded, not yet calibrated. Consequences: a new `hint` content family (table + wire entity + read) under the **ADR-0006 second amendment**, executed with the generator build; server-side context assembly (exclusion never client-trusted); authored seed rungs until the generator ships.
- [ADR-0013: Subject-Coach Test Mode — test blueprint, governed test generation, and the client-integrity stance](0013-subject-coach-test-mode-blueprint-generation-integrity.md) — **Accepted, with conditions — 2026-07-02** (was Proposed 2026-07-02; ratified conditionally at the build-sequencing human gate).
