# GoalJudge Step 1 Open-Code Inventory

## Scope and posture

- Inputs used for this inventory:
  - `docs/research/goaljudge_synthetic_dimension_space.md` (codebook taxonomy and definitions)
  - `docs/research/goaljudge_phase2b_open_coding.md` (saturation chronology and first observation batches)
  - `docs/reports/goaljudge_manual_walkthrough_gj001_gj022_session_report.md` (session-emergent environment/judge codes)
  - `docs/research/goaljudge_phase3_axial_coding.md` (Axis B/C canonical naming and contamination framing)
- Inventory includes:
  - 16 active agent-behavior failure codes (+ 1 retired: `tool-stub-limitation` — see retirement note)
  - 2 judge-quality codes
  - 1 non-failure baseline (`correct-complete`)
  - emergent environment/judge drift codes surfaced in the GJ-001 to GJ-022 session
- Retirement note:
  - `tool-stub-limitation` (Phase 2b §3.10) is **RETIRED** as an agent-behavior code now that live web search (SearXNG) replaces the batch web-search stub. The "failure" it named was a batch-environment artifact (an Axis-B confound), not agent behavior. The row is kept for provenance but excluded from the active agent-behavior count. Downstream alignment: Step 2 Axis-A clusters drop it from A3 (16 active codes); Phase 3 §3/§6 annotate it as retired pending the post-SearXNG batch re-run.
- Alias handling:
  - Where the same concept appears under multiple names, one canonical row is retained and aliases are recorded in `alias_note`.
  - `lf-goal-met-drift` and `lf-criteria-drift` are retained as session surface manifestations and mapped back to their judge-quality parent codes.
- `first_seen_case` semantics:
  - For codebook-origin rows, first-seen points to Phase 2b synthetic-batch chronology (`Cases1-47`) where available.
  - For session-emergent rows, first-seen points to manual walkthrough case IDs (`GJ-001` to `GJ-022`).
  - Some rows include both provenances when a code is out-of-corpus in Phase 2b but observed in the manual session.
- `example` / `example_ref` semantics:
  - `example` — short prose excerpt from a real trace (final answer, tool output, or Langfuse/session observation); truncated to ~120 chars in this markdown table (full text in CSV).
  - `example_ref` — case ID, trace prefix, and source file (`GCP-UI` / `logs/evals.log` / `stress_fixtures.py`).
  - Source priority: GCP UI session (`goaljudge_step0_environment_table.csv`) when available, else Phase 2b batch `logs/evals.log`, else judge-stress fixtures.
